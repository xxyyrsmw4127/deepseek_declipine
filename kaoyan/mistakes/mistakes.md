### 用户自撰错因（原文留档，质量高）

- **Q11** 误选 A → 正解 **D** ｜ **C 概念（绝对化表述）**
  - 链式存储 ≠「长度不受限制」：动态分配受物理内存与虚拟地址空间限制，OOM 客观存在，「不受限」是绝对化错误表述
  - D 的落点：顺序（循环）队列可用 `(rear-front+MaxSize)%MaxSize` 在 **O(1)** 算出元素个数；普通链式队列只有 front/rear 两个地址、不额外维护 `length` 就必须 **O(n)** 遍历 → 这是链式队列的固有特性
  - 附带排除：B（两者入队出队均 O(1)，渐进效率相同）、C（链式可顺 next 顺序访问，队列不支持的是**随机访问**）
- **Q13** 误选 C → 正解 **D** ｜ **C 概念（循环链表的首尾可达性）**
  - 题干实质 =「只给首/尾指针之一，找另一端是否需要遍历」
  - A 项（只给 front、非循环）最不适合：找队尾须从队首顺 next 走 **O(n)**
  - B/C/D 均可 O(1) 双向到达（带尾指针的**单向循环**链表可经 `rear->next`，带头结点则跳过头结点，取队首）
- **Q16** 误选 C → 正解 **D** ｜ **C 概念（封口原则）**
  - 误选根源：**默认「新结点的指针域已经初始化为 NULL」**；而题干只说「`x` 所指元素需入队」，**未声明 `x->next` 已置空**
  - C（`rear->next = x; rear = x;`）只改两个指针 → 新队尾的 `next` 指向内存垃圾 → 遍历时野指针
  - **408 潜规则**：尾插（入队）除链接旧尾、推进 rear 外，**新结点的 `next` 必须显式封口为 NULL**；同批出现「只改两指针」（C）与「含 NULL 封口」（D）时选语义完整的 D
- **Q21** 误选 D → 正解 **B**（front 初值 0、rear 初值 **n-1**）｜ **C 概念（指针定义决定初值）**
  - **入队只移动 rear，绝不动 front**（出队才动 front）→ 入队后 front 仍为初始值，而首元素在 `A[0]` ⇒ `front_初 = 0`
  - rear 指向**队尾当前元素**时，入队须「先 `rear=(rear+1)%n` 再写 `A[rear]`」→ 令首次入队后 `rear=0` ⇒ `(rear_旧+1)%n = 0` ⇒ **`rear_旧 = n-1`**
